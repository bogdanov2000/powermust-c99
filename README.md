# powermust-c99

Переносимый драйвер **Megatec Q1/F на C99** для коробочки управления
воротами. Основан на анализе [syssi/esphome-powermust](https://github.com/syssi/esphome-powermust),
но ядро написано заново: без ESPHome, C++, Arduino, динамической памяти и float.
Код, API и пример ATmega328P подробно прокомментированы по-русски.

**Статус:** драйвер и автоматические тесты; совместимость с конкретным
ELTENA пока не подтверждена физическим обменом. Пример ATmega328P — мониторинг,
а не готовая прошивка ворот. Автоматика реле, Modbus, OTA, watchdog и
управление отключением нагрузки в этот перенос не входят.

## Главное для нашей коробочки

- `Q1` читает текущие параметры и 8 флагов; `F` — номинальные параметры.
- В `Q1` **нет процента заряда**. `load_percent` — нагрузка ИБП, не заряд АКБ.
  Из этих данных нельзя автоматически получить достоверные пороги 70/90%.
- `battery_cV` может означать напряжение батареи **или ячейки**: семантику
  проверяют на конкретной модели. Драйвер не умножает его произвольно.
- Отсутствие ответа на команду — `PM_SENT_UNCONFIRMED`, а не «исполнено».
- Недоступные поля `@` помечаются через `valid_fields`; неизвестное значение
  нельзя трактовать как реальный ноль.
- Достоверность для решений: свежий `Q1` **и** присутствие нужного поля.
  Ответ `F`, шум UART и отправка команды не продлевают свежесть `Q1`.
- Команды управления выключены по умолчанию. Включаются явным
  `config.allow_control = true` после проверки модели и условий исполнения.

## Проверка на компьютере

```sh
make all test
make sanitize
./build/host-demo
```

Нужны компилятор C99 и make. Сборка использует строгие предупреждения
как ошибки и `-pedantic-errors`. `make sanitize` включает ASan и UBSan.
В контейнерах под ptrace LeakSanitizer может быть недоступен; для такого
окружения: `ASAN_OPTIONS=detect_leaks=0 make sanitize`.

```sh
# Нужны avr-gcc, avr-libc, binutils-avr:
make avr
```

Получатся `build/atmega328p.elf` и `build/atmega328p.hex`; `avr-size` покажет
реальный расход Flash/RAM. HEX является только примером чтения ИБП.
При 8 МГц необходимо пересчитать Timer0 и UART: пример намеренно отклоняет
неподдерживаемую частоту, а не выдаёт неверное время.

Шаблон CI сохранён в `ci/c99.yml`. Он пока не активен: текущий доступ
GitHub не имеет права `workflow`. Для включения Actions владелец переносит
его в `.github/workflows/c99.yml` через доступ с соответствующим правом.

## Минимальная интеграция

```c
static pm_context ups; /* Статическая память, не на малом стеке AVR. */

/* uart_read: 1 байт / 0 пусто / -1 ошибка, без ожидания.
 * uart_write: true, только если принята вся посылка. */
pm_config cfg = pm_default_config(uart_read, uart_write, uart_user);
pm_result initialized = pm_init(&ups, &cfg, milliseconds());
/* Проверить initialized == PM_OK до первого pm_service(). */

/* В основном цикле, часто, например каждые 1..10 мс: */
uint32_t now = milliseconds();
pm_service(&ups, now);
bool flags_usable = pm_status_fresh(&ups, now, 30000u) &&
    (ups.status.valid_fields & PM_Q1_FLAGS_VALID) != 0u;
if (flags_usable) {
    bool mains_failed = (ups.status.flags & PM_FLAG_UTILITY_FAIL) != 0u;
    /* Передать mains_failed своей логике; здесь нет управления воротами. */
}
```

Все callback и `pm_service()` выполняются в одном основном цикле.
В ISR допустимы только UART-кольца и таймер. Нельзя вызывать драйвер
из ISR или одновременно из нескольких задач.

Начальные параметры: Q1 каждые 2 с, F каждые 60 с, timeout 1 с,
тихий интервал между транзакциями/после ошибки 1 с. Из-за интервала тишины
фактический период зависит от длины ответа и очереди. Очередь содержит
4 ожидающие команды, плюс отдельную активную.
