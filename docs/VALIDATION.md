# Результаты проверки — 12 октября 2026

## Host C99

Команды:

```sh
make all test
ASAN_OPTIONS=detect_leaks=0 make sanitize
./build/host-demo
```

Строгий `-std=c99`, `-pedantic-errors`, `-Wall -Wextra -Wpedantic
-Werror -Wconversion -Wshadow -Wstrict-prototypes`.

Результат обычного и ASan/UBSan запуска:

```text
PASS: 100467 checks; parser, UART, queue, recovery, clock rollover, random input
```

Это число проверенных утверждений, а не 100467 отдельных сценариев.
В числе сценариев — 20000 случайных входов для двух parser.
LeakSanitizer выключен только при локальном запуске в контейнере,
поскольку его проверка процессов недоступна под ptrace. Проверки
границ памяти AddressSanitizer и неопределённого поведения UBSan включены.
Сам протокольный драйвер вообще не использует динамическую память.

Host-demo прошёл: Q1/F сформированы с CR, ответы разобраны, свежесть Q1
вернулась true. sizeof контекста на этой host-архитектуре — 288 байт;
размер на AVR отличается из-за размеров указателей и выравнивания.

## Реальная кросс-компиляция AVR

Инструменты: Ubuntu jammy `gcc-avr` 5.4.0 + Atmel 3.6.2,
`avr-libc` 2.0.0, `binutils-avr` 2.26. Пакеты распакованы во временный
каталог, без изменения системной установки.

```sh
make avr
```

Собраны `src/powermust.c` и `examples/atmega328p/main.c` для
`-mmcu=atmega328p -DF_CPU=16000000UL`, оптимизация `-Os`, удаление
неиспользуемых секций. Те же строгие предупреждения остались ошибками.
Получены ELF и HEX.

```text
Device: atmega328p
Program: 4806 bytes (14.7% Full)
Data:     355 bytes (17.3% Full)
```

4806 байт — Flash проверочного примера. 355 байт — статические
`.data + .bss + .noinit`, включая UART-кольца и контекст.
**Стек, загрузчик Arduino, Modbus и другая автоматика в эту оценку
не входят.** При интеграции нужно вновь измерить размер всей прошивки
и запас стека в реальных условиях.

## Что ещё не проверено

Физическая плата, RS232-распиновка и обмен с конкретным ELTENA,
процент заряда, команды выключения и поведение при возврате сети.
Автомат ворот, Modbus, OTA и загрузчик не входят в этот проект.

Конфигурация Actions сохранена в `ci/c99.yml` как неактивный шаблон:
у доступа GitHub отсутствует право `workflow`. Проверки выше были
выполнены отдельно, а не выданы за успешно запущенный GitHub Actions.
