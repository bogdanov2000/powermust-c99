# Разбор syssi/esphome-powermust и перенос на C99

Дата анализа: 12 октября 2026 года. Проанализированы `powermust.cpp`,
`powermust.h`, README, switch-конфигурация и тесты исходного проекта.
Исходники зафиксированы по tree
`63e07048d89b90c6fb583911fc6758cfc2be69b1` и blob основного файла
`25fdeef07148b449f419994aa8ef393ecb927dda`.

## Что делает исходный проект

Это внешний компонент ESPHome для Mustek PowerMust 800 USB.
Он подключается по UART через преобразователь RS232/TTL, отправляет
ASCII-запросы с CR, получает строки с CR и публикует сенсоры ESPHome.
В примере используется 2400 8N1.

`Q1` имеет 7 числовых полей и 8 ASCII-битов. `F` имеет 4 поля.
Добавление сенсора автоматически добавляет соответствующий запрос в
список опроса. Переключатели ставят строки в очередь управляющих команд.
Состояния `POLL_COMPLETE → POLL_CHECKED → POLL_DECODED` распределяют
обработку по нескольким проходам `loop()`.

Весь репозиторий нельзя буквально перевести на C: YAML и Python
создают ESPHome-сущности, а классы наследуются от UARTDevice и
PollingComponent. В C99 переносится протокольное ядро, а интеграция
с HA/Modbus/OTA остаётся задачей внешнего ПО.

## Обнаруженные проблемы

| Место | Наблюдение | Последствие для коробочки | Исправление |
|---|---|---|---|
| Приём в `loop()` | Массив 110 байт; CR записывается с увеличением `read_pos_`, затем NUL по следующему индексу | Если CR оказался 110-м байтом, NUL пишется вне массива | Буфер 96, полезная длина максимум 95, место NUL зарезервировано |
| Переполнение приёма | `read_pos_` сбрасывается, UART очищается, но текущий байт продолжает записываться | Хвост повреждённого ответа может выглядеть как новый пакет | Завершение с PM_OVERFLOW, слив хвоста и период тишины |
| `STATE_POLL_COMPLETE` | Проверяется только начало `(NAK`; длина/формат перед разбором не проверяются | Усечённый ответ может попасть в разбор чисел и флагов | Точное число токенов, диапазоны, 8 бит, явная длина |
| `strtof/strtol` | Не контролируются продвижение указателя, NaN/Inf, переполнение и `@` | Мусор может стать нулём либо невалидным значением сенсора | Ограниченный ASCII parser, fixed point, valid_fields |
| Чтение флагов | 8 символов читаются без подтверждения их наличия и значений 0/1 | Чтение за строкой или ложное состояние сети/АКБ | Проверка всех символов до обновления status |
| `send_next_command_()` | Локальный `byte_command[16]` заполняется по длине произвольной строки, хотя затем не используется | Более 16 байт могут переписать стек | Буфер удалён, длина и грамматика команд ограничены |
| `queue_command_()` | Произвольные строки, 10 `std::string`; переполнение только логируется | Нет явного результата для Modbus/приложения; динамическая память | 4 фиксированных слота и PM_QUEUE_FULL |
| Timeout управляющей команды | Тишина трактуется как «Command successful» | Обрыв RS232 выглядит как успешное отключение | PM_SENT_UNCONFIRMED; исполнение подтверждается отдельно |
| Свежесть | Нет отдельного времени последнего проверенного Q1 для логики коробочки | Старый статус может выглядеть текущим | has_status, last_q1_ok_ms, pm_status_fresh |
| `Q` | Один и тот же код назначен ON и OFF beeper | Повтор команды снова меняет состояние | Документирована семантика toggle, автоматических повторов нет |
| Тесты | Проверяют в основном корректные значения опубликованных сенсоров | Не покрыты повреждения/буфер/связь/таймер | Отдельные UART/state-machine тесты и ASan/UBSan |

Дефект предельного буфера следует непосредственно из последовательности
записи в исходнике. Даже если оптимизация уберёт неиспользуемый
`byte_command`, его исходная логика небезопасна и не переносится.
Это анализ кода, а не заявление об эксплуатации дефектов на реальном ИБП.

## Протокол и реальные ограничения

| Поле Q1 | Наш тип/единица | Значение |
|---|---|---|
| Входное напряжение | input_cV, 0.01 В | Текущее напряжение входа |
| Напряжение сбоя | fault_cV, 0.01 В | Зафиксированное напряжение нарушения сети |
| Выходное напряжение | output_cV, 0.01 В | Текущее напряжение выхода |
| Нагрузка | load_percent, целые % | Нагрузка ИБП; не ёмкость АКБ |
| Частота | frequency_cHz, 0.01 Гц | Частота сети |
| Напряжение АКБ | battery_cV, 0.01 В | Батарея/ячейка в зависимости от модели |
| Температура | temperature_cC, 0.01 °C | Температура; допускается отрицательная |
| Флаги | flags, uint8_t | ASCII b7..b0 преобразованы в битовую маску |

`Q1` не передаёт процент заряда. Документация NUT перечисляет расширения
`BL`, `BL?`, `QBL` и другие, но подчёркивает, что поддержка зависит от
модели. Их нельзя автоматически приписывать ELTENA или реализовывать
«по догадке». Для 70/90% нужен реальный обмен и подтверждённый формат.

Бит 5 означает **bypass/boost/buck**. Нельзя без проверки модели назвать
его чистым признаком bypass. Бит 3 описывает standby/online; он не
задаёт универсальный множитель напряжения для произвольного устройства.

В базовом Megatec нет CRC и номера запроса. Проверка грамматики отсекает
много повреждений, но не обнаружит превращение одной ASCII-цифры в
другую допустимую цифру. Приложение может дополнительно проверять
правдоподобие/стабильность значений, не выдавая это за CRC.

## Почему такое ядро подходит ATmega328P

Динамической памяти нет. В UART-буфере 96 байт, команде 9 байт,
очереди 4 слота. Контекст приложения размещается статически.
Числа хранятся как целые с масштабом 100, что упрощает передачу через
Modbus и исключает тяжёлое преобразование float.

Основной цикл не ждёт CR и не спит в timeout. За один вызов вычитывает
максимум 64 байта и сразу отдаёт управление. Отдельный UART-адаптер
обеспечивает неблокирующее чтение/запись; пример для AVR делает это
через два кольцевых буфера и ISR.

## Проверка переноса

Тесты используют известные ответы upstream и пример NUT с напряжением
ячейки 2.05 В. Проверяются все 8 флагов отдельно, отрицательная
температура, недоступные поля, точные сотые, переполнение числа,
усечения, неправильное число полей, CR-инъекции в команды и
20 000 детерминированных случайных входов.

Для автомата проверены побайтовый приём, CRLF, Q1/F, отказ NAK,
таймаут, длинный пакет, UART-ошибка, неуспешная запись, поздний хвост,
лимит работы за проход, FIFO, отсутствие повторов команд, голодание F,
свежесть и переполнение uint32_t таймера.

Host-сборка проверена со строгим C99 и ASan/UBSan. Шаблон задачи CI
для ATmega328P сохранён в `ci/c99.yml` и пока не активирован: текущий
GitHub-доступ не имеет права `workflow`. Компиляция AVR, независимо
от места запуска, не заменяет проверку UART на реальной плате.
